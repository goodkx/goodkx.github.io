PART 1 / 计算机网络 · 第 4 章

网络层

它不关心你用什么网线、连哪个 Wi-Fi。
它只干一件事：把 IP 数据报，从源主机一路送到目的主机。

逻辑通信 尽力而为 无连接 路由 + 转发
4.1 概述

网络层：一家只承诺「尽力」的快递公司

NET / 01

📦 它只做两件事

  • 转发（Forwarding）：路由器收到分组，查表、从哪个口出去 —— 局部动作，纳秒级
  • 路由选择（Routing）：全网一起算，哪条路最合适 —— 全局动作，秒级

🪄 什么叫「逻辑通信」？

从传输层往下看，源主机和目的主机好像一条直连的线；
实际上中间要穿过很多路由器、很多种链路（光纤、Wi-Fi、4G）。
网络层把这堆复杂细节全部藏起来，只露出一个「IP 地址」。

⚠️

「尽力而为」= 不保证。不保证送到、不保证不重复、不保证按序。可靠性交给运输层 TCP 负责。

4.1 两种服务

寄快递：一次一单 vs 打专线电话

NET / 02

数据报服务

IP 采用
  • 每个分组独立选路，各走各的
  • 可能乱序、重复、丢失
  • 网络不维护连接状态，简单、便宜、能扛规模
  • 可靠性交给端系统（TCP）
  • 代表：IP
VS

虚电路服务

早期网络
  • 通信前先建立连接，分配一条路径
  • 所有分组走同一条路，按序到达
  • 网络负责可靠性，路由器要记连接状态
  • 节点故障影响大，扩展性差
  • 代表：X.25 帧中继 ATM

🤔 为什么互联网最后选了数据报？

因为互联网要连接无数异构网络：有的可靠、有的不可靠。把可靠性统一压到端系统，网络层就能做得又简单又快，出了故障也只影响局部。

📝 一句话答题模板

「IP 层提供无连接、不可靠的数据报服务；可靠性由运输层保证。」
考到「网络层提供什么服务」就写这句。

4.2 IP 地址

IP 地址 = 32 位二进制门牌号

NET / 03

写成「点分十进制」最好看

4 组 × 8 位
192.168.1.10
11000000 10101000 00000001 00001010

每个数字 0~255，四个数字拼起来就是 32 位

结构

网络号 + 主机号

网络号 net-id标志「在哪个网络」
主机号 host-id标志「网络里的哪台机」
🏠

IP 地址不是「哪台电脑」的永久名字，而是这块网卡在这个网络里的位置 —— 换网络就得换地址。

🔢 换算不用怕

只要记住：
11111111 = 255
11000000 = 128 + 64 = 192
10101000 = 128 + 32 + 8 = 168

🧠 记忆钩子

把 IP 想成「小区名 + 门牌号」：
网络号告诉你哪个小区，主机号告诉你几零几。

4.2.4 子网划分

把一个大班级，隔成几个小班

✂️ 三级结构：网络号 → 子网号 → 主机号

网络号原封不动
子网号从主机号借来的
主机号剩下的位数

借 n 位做子网号 → 能分 2ⁿ 个子网；
剩下 m 位做主机号 → 每个子网 2ᵐ − 2 台主机。

4.3 无分类编址

CIDR：地址后面加个「/n」就完事

NET / 08

🎯 核心思想：不再分 A/B/C

写成 a.b.c.d/n，n 就是网络前缀长度。
例如 200.100.1.0/24 表示前 24 位是网络前缀，剩 8 位给主机。
地址块大小 = 2^(32−n)

🧩 路由聚合（超网）

把多条前缀相同的路由合成一条，减小路由表。

200.100.0.0/24 200.100.1.0/24 200.100.2.0/24 200.100.3.0/24

前 22 位相同 → 聚合成 200.100.0.0/22

🏆 最长前缀匹配

路由表里有多条都能匹配时，选前缀最长（最具体）的那条。

200.100.0.0/22→ 出口 A
200.100.1.0/24→ 出口 B（胜出）
0.0.0.0/0→ 默认路由

🧮 块大小速算

块大小 = 2(32−n)。/24 → 256；/26 → 64；/28 → 16；/30 → 4。子网起点一定是块大小的整数倍。

🏃

「最长前缀匹配」就是最具体的优先。目标地址 200.100.1.77 同时匹配 /22 和 /24，选 /24。

4.2.4 ARP

ARP：拿着门牌号，问出身份证号

NET / 09

🆔 先分清两种地址

IP 地址

逻辑地址，32 位，可变。
相当于「收货地址」。

MAC 地址

物理地址，48 位，烧在网卡里。
相当于「身份证号」。

📢 ARP 的工作方式

  • 先查 ARP 高速缓存，有就直接用
  • 没有 → 在本局域网广播 ARP 请求
  • 目标主机单播回复自己的 MAC
  • 结果写入缓存，下次不用再问

🔀 跨网段时，MAC 会变、IP 不变

链路源 MAC目的 MAC
主机 → 路由器主机网卡路由器接口
路由器 → 主机路由器接口目标主机

IP 数据报的源/目的 IP 始终不变；MAC 帧每过一跳就换一次「信封」。

📮

IP 是最终收件人，MAC 是这一站送快递的小哥。包裹一路转手，收件人名字不会改。

4.2.5 数据报格式

IP 数据报首部：一张 20 字节的快递单

NET / 10
版本4 位
首部长度4 位
区分服务8 位
总长度16 位
标识 Identification16 位
标志3 位
片偏移13 位
生存时间 TTL8 位
协议8 位
首部检验和16 位
源 IP 地址32 位
目的 IP 地址32 位

固定部分 20 字节；可选字段最多 40 字节，总首部最长 60 字节。

首部长度

单位是 4 字节。最小值 5（20 字节），最大值 15（60 字节）。

总长度

单位是 字节，最大 65535。= 首部 + 数据。

TTL 生存时间

每过一个路由器减 1，减到 0 就丢弃并回 ICMP 超时。防止分组在环里打转。

协议字段

TCP=6，UDP=17，ICMP=1，OSPF=89 —— 告诉目的主机「数据交给谁」。

🔍

首部检验和只校验首部，不校验数据；每经过一个路由器都要重新计算（因为 TTL 变了）。

🚩

标志位：DF=1 禁止分片；MF=1 表示后面还有片；MF=0 表示这是最后一片。

重点计算

分片：过不了 MTU，就把包裹拆开

NET / 11

📦 为什么要分片

每种链路有最大帧长，能携带的 IP 数据报上限叫 MTU（以太网通常 1500 字节）。超了就得拆。

🧩 三个字段配合

  • 标识：同一原始数据报的片，标识相同
  • MF：还有后续片 = 1，最后一片 = 0
  • 片偏移：本片数据在原始数据中的位置 ÷ 8

注意：片偏移的单位是 8 字节，所以每片数据长度必须是 8 的倍数（最后一片除外）。

⚠️

分片可以发生在源主机或中间路由器；但重组只在目的主机做。

✍️ 例题：4000 字节数据报过 1500 MTU

首部 20 字节 → 每片最多携带 1500 − 20 = 1480 字节数据。

片数据长度片偏移MF
第 1 片148001
第 2 片14801851
第 3 片10203700

偏移算法：1480 ÷ 8 = 185；第二片起点 1480 → 1480 ÷ 8 = 185；第三片起点 2960 → 370。

🧮

原始数据报总长 4000（含首部 20），数据部分 3980 = 1480 + 1480 + 1020。最后一片不必是 8 的倍数。

4.4.3 ICMP

ICMP：包裹送不到，至少给你个说法

NET / 13

😖 差错报告报文（5 种）

  • 终点不可达：目的地找不到
  • 源点抑制：我太忙了，你慢点发（已很少用）
  • 时间超过：TTL 减到 0，分组被丢
  • 参数问题：首部字段有错
  • 改变路由（重定向）：下次走另一个网关

🙅 不发送差错报文的几种情况

对 ICMP 差错报文不再发差错报文；
对非第一个分片不发；对多播地址不发；对特殊地址（127、0.0.0.0）不发。

🏓 ping 的原理

发送 回送请求（Echo Request），对方回 回送应答（Echo Reply）。测的是往返时间 RTT 和连通性。

🛰️ traceroute 的原理

从 TTL=1 开始逐次加 1。每经过一个路由器 TTL 减到 0，路由器回一个「时间超过」报文 —— 这样就把沿途每一跳的 IP 都套出来了。

📦

ICMP 报文装在 IP 数据报里发送，不是独立协议，协议号 = 1。

4.5 路由器

路由器：一个高速分拣中心

NET / 14

⚙️ 收到分组后发生什么

  • 物理层收比特 → 链路层拆帧
  • 检查目的 IP，查转发表
  • TTL 减 1，重算首部检验和
  • 重新封装成新帧，从对应端口发出去

转发

查表、搬数据，快

路由选择

跑协议、算路径，慢

🚦

输入端口如果来不及处理，会在缓存里排队；排满了就丢包 —— 这就是拥塞丢包。

4.6 路由选择

路由协议：全网路由器一起「对答案」

NET / 15
静态

手工配路由

管理员一条条写。简单、不耗 CPU，但网络一变就得重配。

适合：小网络、边缘路由器、默认路由

动态

协议自动算

路由器互相交换信息，自动算出转发表。能适应故障和拓扑变化。

适合：中大型网络、互联网主干

分层

AS 自治系统

把互联网切成很多个「自治区」，每个 AS 内部自己管，外部只交换可达性。

IGP 管内，EGP 管外

🗺️ 两大类路由协议

IGP

内部网关协议：在一个 AS 内部用，如 RIP、OSPF。目标是找最短/最快路径。

EGP

外部网关协议：AS 之间用，目前基本只有 BGP。目标是可达 + 策略，不是最短。

🎯 路由算法的两条路线

距离向量：只跟邻居聊天，交换「我到各处的距离」。代表 RIP。
链路状态：全网洪泛拓扑，自己算最短路。代表 OSPF。

4.6.2 RIP

RIP：只数「跳几次」，16 跳算迷路

NET / 16

📣 工作方式：和邻居唠嗑

  • 每个路由器只和相邻路由器交换信息
  • 交换的内容是整张距离向量表（到每个网络的距离）
  • 距离用跳数衡量，直连 = 1
  • 每 30 秒 广播一次，走 UDP 520 端口

📏 距离规则

最大跳数 15，16 表示不可达。
所以 RIP 只适合小型网络，直径不能超过 15 跳。

🐢

经典缺陷：「好消息传得快，坏消息传得慢」。一条链路断了，要很久才能传播到全网（计数到无穷问题）。

🔄 距离向量更新口诀

①

先把邻居表里所有距离 +1

②

下一跳改成那个邻居

③

和本表逐项比，更小就替换

④

30 秒没收到邻居更新 → 标记 16

🧠 一句话记住

RIP = 道听途说：我相信邻居说的距离，再加 1 传给别人。

4.6.3 OSPF

4.6.4 BGP

BGP：自治区之间的「外交谈判」

NET / 18

🌍 它解决什么问题

互联网有几十万个 AS。每个 AS 有自己的「政策」：谁能过、谁不能过、走哪便宜。
BGP 交换的不是「最短距离」，而是可达性 + 路径属性。

📌 关键点

  • 基于 TCP 179 端口，可靠传输
  • 交换的是路径向量：到某网络要经过哪些 AS
  • 用 AS 路径防环：看到自己的 AS 号就丢弃
  • 每个 AS 选一个 BGP 发言人

🆚 和内网协议的区别

维度RIP / OSPFBGP
范围AS 内部AS 之间
目标最短路径可达 + 策略
承载UDP / IPTCP 179
规模小 / 中全网
🤝

BGP 更像商务合作：不是「哪条路最近」，而是「跟谁合作更划算、更安全」。

4.8 NAT

NAT：全家共享一个门牌号

NET / 20

🏠 问题：IPv4 地址不够用

家里 5 台设备，只有 1 个公网 IP。怎么办？
NAT 让私有地址在出口路由器被换成公网地址，回来时再换回去。

🔁 NAPT：靠端口号区分

内网地址:端口→公网地址:端口
192.168.1.2:5000→203.0.113.5:61001
192.168.1.3:5000→203.0.113.5:61002

同一个公网 IP，用不同端口区分不同内网主机 —— 这就是 NAPT（端口多路复用）。

✅

🧠

IO / 07

🥇 判优：两个做法

  • 硬件排队器：电路固定优先级，快
  • 软件查询：按顺序查标志位，灵活但慢

优先级一般：故障 > DMA > 外设；高速设备优先于低速设备。

🙈 中断屏蔽字

每个中断源有一个屏蔽字：某位为 1，表示「我可以屏蔽掉它」。
修改屏蔽字，就能动态调整优先级。

📍 中断向量

每个中断源对应一个向量地址，里面存着中断服务程序的入口地址。CPU 识别中断源后，靠它跳过去。

🎚️

屏蔽不是「关掉设备」，而是「先别来打扰我」。

🪆 多重中断（中断嵌套）

高优先级中断可以打断低优先级的中断服务程序，形成嵌套。

主程序 → 中断 A → 中断 B（更急） → 返回 A → 返回主程序

🔑 实现嵌套的关键

进入中断服务程序后要提前开中断（STI），否则新中断进不来，就没法嵌套。

注意：保存现场必须在开中断之前完成，否则会被覆盖。

5.6 通道

通道：一台专门管 I/O 的小处理器

IO / 11

🧠 通道 vs DMA

DMA 一次只能管一台（或少数几台）设备的一次数据块传送；
通道能执行通道指令，一次控制多台设备，是「弱化的处理器」。

🗂️ 三种通道类型

  • 字节多路通道：多个低速设备，按字节交叉服务
  • 数组多路通道：多个高速设备，按数据块交叉服务
  • 选择通道：一次只服务一台高速设备，独占通道

📜 通道靠什么工作

执行通道指令（通道程序），指令放在主存里。CPU 只需在 FCB / CAW 中写清「从哪读、写到哪、多少字节」。

⚖️ 三种通道对比

类型服务对象方式典型
字节多路多台低速字节交叉键盘、终端
数组多路多台高速块交叉磁盘
选择单台高速独占磁带

记忆：字节多路管「多而慢」，数组多路管「多而快」，选择通道管「一台快的」。

👔

通道像外包的后厨团队：主厨只说「准备 100 份套餐」，剩下怎么分工、谁先做，全由团队长安排。

📐 容量公式

容量 = 记录面数 × 磁道数/面 × 扇区数/道 × 扇区容量

磁盘地址 = 柱面号 + 磁头号 + 扇区号。寻道找柱面，选头定盘面，旋转等扇区。

🐢 为什么磁盘「慢」

寻道时间占大头，通常几毫秒；机械动作决定了它和内存差好几个数量级。这也是 SSD 存在的理由。

⏱️ 存取时间 = 三段时间之和

寻道

磁头移到目标磁道，最慢

旋转

等目标扇区转到磁头下，平均 半圈

传输

读出/写入数据本身

🔁 转速换算

7200 r/min = 120 r/s
平均旋转延迟 = 60 / (2 × 7200) ≈ 4.17 ms
转一圈 = 60 / 7200 ≈ 8.33 ms

手把手例题

转速 7200 转/分，传输率是多少？

IO / 13

题目

磁盘转速 7200 r/min，每个磁道 500 个扇区，每扇区 512 B。求：
① 平均旋转延迟　② 读一个扇区的时间　③ 数据传输率

① 平均旋转延迟

转一圈时间 = 60 ÷ 7200 = 8.33 ms
平均等半圈 = 8.33 ÷ 2 ≈ 4.17 ms

② 读一个扇区

8.33 ms ÷ 500 ≈ 0.0167 ms

③ 数据传输率

每秒转 120 圈，每圈 500 × 512 B：
120 × 500 × 512 B = 30 720 000 B/s
≈ 30.7 MB/s

也可以：512 B ÷ 0.0167 ms ≈ 30.7 MB/s，两种算法互相验证。

📝

答题模板：先写公式 → 代数字 → 带单位。平均旋转延迟一定用「半圈」，不是一整圈。

🧮

若题目给的是「平均寻道时间」，总存取时间 = 寻道 + 旋转 + 传输，三项相加。

输入输出系统 · 答案与解析

QUIZ / 02·A

01 · D

条件只有三个：有请求、开中断（IF=1）、当前指令执行完。服务程序是否已装入内存不是响应条件。

02 · D（一个数据块）

中断按字节/字传送，DMA 按数据块传送，这是两者最核心的区别之一。

03 · 关中断 → 保存断点 → 识别中断源 → 转服务程序

顺序不能乱：先关中断防止打断，再存 PC，然后取中断向量，最后跳转。

04 · 三种方式

① 停止 CPU 访存：DMA 传送时 CPU 暂停访存，简单但浪费；
② 周期挪用：趁 CPU 不访存的周期插入，最常用；
③ 交替访问：CPU 与 DMA 分时交替使用总线，效率高、硬件复杂。

05 · 4.17 ms

60 ÷ 7200 = 8.33 ms/圈，平均等半圈：8.33 ÷ 2 ≈ 4.17 ms。

06 · 约 30.7 MB/s

7200 r/min = 120 r/s；120 × 500 × 512 B = 30 720 000 B/s ≈ 30.7 MB/s。

07 · 三点区别

传送：中断经 CPU，DMA 不经过；单位：字节/字 vs 数据块；请求对象：CPU 处理时间 vs 总线使用权。

08 · 三类通道

字节多路：多台低速设备，字节交叉；
数组多路：多台高速设备，块交叉；
选择通道：单台高速设备，独占。

⚠️

易错点：平均旋转延迟是「半圈」；DMA 结束仍会发中断；通道是处理器，不是简单的数据通路。

多表查询

一张表只讲一件事，真实问题却总横跨好几张表。
多表查询就是：按关系把表拼起来，拼出你要的答案。

连接 子查询 聚合 CTE 性能
先想清楚

为什么数据要拆成好几张表？

SQL / 01

🧹 拆表 = 少写重复、少出错

如果把班级名写进每条学生记录，改一次班级名要改几百行，还容易改漏。
把班级单独存一张表，学生表只存 class_id —— 改一处，全对。

🔗 靠什么把表连起来

  • 主键：唯一标识一行，如 student.sid
  • 外键：引用另一张表的主键，如 class_id
  • 关系：一对一、一对多、多对多
🧠

多表查询的前提不是 SQL 写得多花，而是你先看懂表与表之间的那条线。

连接的本质

所有连接，都是「先配对，再筛选」

SQL / 02

🛒 笛卡尔积 = 每行都去配一遍

左表 3 行、右表 2 行，不加条件直接连，就会得到 3 × 2 = 6 行。绝大多数是没意义的组合。

✂️ 加上 ON 条件才有意义

ON s.class_id = c.class_id
只保留「学生班级号 = 班级号」的组合，6 行筛成 3 行。

⚠️

三张表连接却只写了 1 个条件，结果会爆炸性增长。记住：N 张表至少 N−1 个连接条件。

最常用

INNER JOIN：只保留两边都有的

SQL / 03

写法一 · ON（最推荐）

SELECT s.sname, c.cname FROM student s INNER JOIN class c ON s.class_id = c.class_id;

写法二 · USING（同名列）

SELECT sname, cname FROM student s JOIN class c USING(class_id);

USING 要求两表列名相同，结果里同名列只出现一次。

写法三 · WHERE（隐式连接）

SELECT s.sname, c.cname FROM student s, class c WHERE s.class_id = c.class_id;

等价于内连接，但连接条件和过滤条件混在一起，表一多就难读。

🎯

内连接只输出匹配成功的行。学生没有班级、或班级没有学生，这些行都会消失。

📝

考试写「查询每个学生的班级名」：用 INNER JOIN 或 WHERE 等值 都算对，写法统一更稳。

重点

外连接：没匹配上的，也要留下来

SQL / 04
左表
右表

LEFT JOIN：左表全部保留
RIGHT JOIN：右表全部保留
没匹配的一方，列填 NULL

🎯 典型场景：找「没有选课的学生」

SELECT s.sname FROM student s LEFT JOIN sc ON s.sid = sc.sid WHERE sc.sid IS NULL;

⚠️ 最容易错的坑

左连接后，把右表的过滤条件写在 WHERE 里：

-- 错：NULL 行被 WHERE 干掉，退化成内连接 WHERE sc.grade > 80

正确：条件写在 ON 里，左表仍然全保留。

-- 对 LEFT JOIN sc ON s.sid = sc.sid AND sc.grade > 80
🧠

记法：ON 决定「怎么连」，WHERE 决定「连完筛什么」。外连接时，这个区别会改变结果。

两个特殊连接

自己连自己，和「全都配一遍」

SQL / 05
自连接

同一张表，取两个别名

员工表里既有员工，又有他的经理。要查「谁比谁工资高」，就得把同一张表当成两张表用。

SELECT a.ename, b.ename AS manager FROM emp a JOIN emp b ON a.mgr_id = b.emp_id;

要点：必须起别名，否则数据库分不清是哪个「emp」。

交叉连接

CROSS JOIN = 笛卡尔积

不加任何条件，把两张表所有行两两组合。数据量大时非常危险。

SELECT * FROM student CROSS JOIN class;

真正用途：生成日期序列、排列组合、测试数据。

🤔

面试常问：「自连接和外连接有什么区别？」 —— 自连接看的是「表来源」，外连接看的是「保留哪边」，两者不在一个维度。

进阶

三表连接：把「学生—选课—课程」串起来

SQL / 06

🔗 连接顺序：一条链往下接

student → sc → course

student 通过 sid 连 sc，sc 通过 course_id 连 course。两个连接条件，一个都不能少。

查询：每个学生的选课名和成绩

SELECT s.sname, c.cname, sc.grade FROM student s JOIN sc ON s.sid = sc.sid JOIN course c ON sc.course_id = c.course_id ORDER BY s.sname, c.cname;
⚠️

少写一个 ON，就会和第三张表做笛卡尔积。1000 名学生 × 50 门课 = 5 万行假数据。

🧩 加筛选也加在 WHERE

... JOIN course c ON ... WHERE c.credit >= 3 AND sc.grade >= 90;

连接条件写 ON，业务筛选写 WHERE。

💡

表多时先画 ER 图，再顺着关系写 JOIN，比背 SQL 模板靠谱。

嵌套

子查询：先把「一个答案」算出来

SQL / 07
标量

返回 1 行 1 列

可以当值用：= > < 加减乘除

SELECT sname FROM student WHERE age > ( SELECT AVG(age) FROM student );
列

返回一列多行

配 IN / ANY / ALL 使用

SELECT sname FROM student WHERE sid IN ( SELECT sid FROM sc WHERE grade >= 90 );
行

返回多列一行

用 (a,b) = (子查询)

SELECT * FROM sc WHERE (sid, course_id) = ( SELECT sid, course_id FROM sc WHERE grade = 100 );

📌 子查询可以放三个位置

WHERE（最常见）、SELECT（算列）、FROM（当临时表，需要别名）。

🧠

IN 和 = 的区别：子查询返回多行时只能用 IN；返回单值才能用等号，否则报错「Subquery returns more than 1 row」。

相关子查询

EXISTS：只问「有没有」，不问「是多少」

SQL / 08

🔁 执行方式：外层每行问一次

对 student 的每一行，拿它的 sid 去 sc 里找。找到第一条就返回 TRUE，不再往下找 —— 所以通常比 IN 快。

查询「至少选了一门课的学生」

SELECT sname FROM student s WHERE EXISTS ( SELECT 1 FROM sc WHERE sc.sid = s.sid );

查询「一门课都没选的学生」

SELECT sname FROM student s WHERE NOT EXISTS ( SELECT 1 FROM sc WHERE sc.sid = s.sid );

子查询里写 SELECT 1 就行，EXISTS 不关心选什么列。

⚠️

NOT IN 有 NULL 陷阱：子查询结果含 NULL 时，NOT IN 可能一行都不返回。找「没有」优先用 NOT EXISTS 或 LEFT JOIN ... IS NULL。

可读性

派生表 & CTE：给中间结果起个名字

SQL / 09
派生表

FROM 里的子查询

SELECT cname, avg_grade FROM ( SELECT class_id, AVG(grade) AS avg_grade FROM sc JOIN student USING(sid) GROUP BY class_id ) AS t WHERE avg_grade > 80;

必须给子查询起别名，否则 MySQL 报错。

🧱

派生表 = 临时搭的脚手架：用完就拆，只在当前这条 SQL 里有效。

CTE（MySQL 8.0+）

WITH 先定义，再查询

WITH class_avg AS ( SELECT class_id, AVG(grade) AS avg_grade FROM sc JOIN student USING(sid) GROUP BY class_id ) SELECT c.cname, t.avg_grade FROM class_avg t JOIN class c USING(class_id) WHERE t.avg_grade > 80;

复杂查询拆成「一步一块」，可读性大幅提升；还能被多次引用。

🧠

递归 CTE 用 WITH RECURSIVE，可以查组织架构、菜单树、评论盖楼。

纵向合并

UNION：把两个结果「上下摞起来」

SQL / 10
SELECT sname FROM student WHERE class_id = 1 UNION SELECT sname FROM student WHERE age < 18;
UNION自动去重，可能排序
UNION ALL保留重复，更快
⚡

能确定不会重复时，优先 UNION ALL —— 省掉去重的排序开销。

📏 三条硬性规则

  • 两边列数必须相同
  • 对应列的类型要兼容
  • 列名以第一条 SELECT 为准

🔀 和 JOIN 的区别

JOIN 是左右拼列（变宽）；
UNION 是上下拼行（变长）。

JOIN
→ 列变多
UNION
→ 行变多
📝

ORDER BY 只能写在最后一条 SELECT 之后，作用于合并后的整体。

统计

连接 + 分组：一次算出每班平均分

SQL / 11
SELECT c.cname, COUNT(sc.sid) AS 人数, AVG(sc.grade) AS 平均分, MAX(sc.grade) AS 最高分 FROM class c JOIN student s USING(class_id) JOIN sc USING(sid) GROUP BY c.class_id, c.cname HAVING AVG(sc.grade) >= 80 ORDER BY 平均分 DESC;
🧠

WHERE 在分组前筛行，HAVING 在分组后筛组。聚合函数不能写在 WHERE 里。

🔢 COUNT 的小陷阱

COUNT(*)：数行数，NULL 也算
COUNT(列)：跳过该列的 NULL
COUNT(DISTINCT 列)：去重后数

📐 执行顺序（重点）

FROM → JOIN → WHERE → GROUP BY → HAVING → SELECT → ORDER BY → LIMIT

⚠️

SELECT 里的别名，WHERE 里不能用，但 ORDER BY 里可以 —— 因为 ORDER BY 在 SELECT 之后执行。

4.1 概述

为什么软件工程最后选了「对象」

OO / 01
结构化方法

以「功能 / 过程」为中心

  • 先分解成函数、模块
  • 数据与操作分离
  • 需求一变，函数链路大改
  • 复用粒度小，难跨项目

适合流程稳定、变化少的系统。

面向对象

以「对象 / 职责」为中心

  • 先找业务里的名词 → 类
  • 数据与操作封装在一起
  • 用多态应对变化，改一处不动全身
  • 类可复用、可继承、可替换

适合需求频繁演进的大型系统。

🧩

更贴近人类思维：现实世界就是由对象组成的，不是由函数组成的。

🔁

更好应对变化：新增一种支付方式，只加一个类，不改原来的调用代码。

🛠️

更易维护复用：封装边界清晰，团队可以并行开发不同类。

4.2 基本概念

六个词，撑起整个面向对象

OO / 02
对象

现实中的那个东西

有状态（属性）和行为（方法）。
例如：张三、这张订单。

类

对象的「模板」

描述一类对象共有的属性和方法。
类是抽象的，对象是具体的。

封装

把细节藏起来

对外只暴露必要接口，内部实现随便改。
关键词：信息隐藏。

继承

子承父业

子类拥有父类的属性和方法，还能扩展。
表达 is-a 关系。

多态

同一个消息，不同反应

父类引用指向子类对象，调用同名方法走子类实现。运行时绑定。

消息

对象之间怎么说话

对象 A 调用对象 B 的方法，就是发一条消息：接收者 + 方法名 + 参数。

🧠

一句话串起来：类定义模板 → 创建对象 → 对象封装状态 → 通过消息协作 → 继承复用代码 → 多态支持替换。

对答案

面向对象 · 答案与解析

QUIZ / 04·A

01 · 部分能否独立存活

聚合：空心菱形，部分可独立存在（班级 ↔ 学生）；组合：实心菱形，同生共死（订单 ↔ 订单项）。

02 · 必然 vs 条件

include：一定会执行，如「选课」包含「登录」；extend：满足条件才执行，如「选课」扩展「申请扩容」。

03 · 三句话

封装：隐藏实现、只露接口，如银行账户只提供存取方法；继承：子类复用父类，如研究生继承学生；多态：同一消息不同响应，如「支付」接口有微信、支付宝两种实现。

04 · 参与者与用例

参与者：读者、管理员（可加「借阅系统」外部服务）。
用例：借书、还书、续借、查询图书、挂失、缴纳罚金。

05 · 中间类拆多对多

引入 Enrollment（选课）：Student 1—* Enrollment *—1 Course。中间类放成绩、选课时间、状态等「关系自身的属性」。

06 · 时间 vs 结构

顺序图强调消息的时间顺序；通信图强调对象之间的链接结构，用序号表示顺序。

07 · 谁有数据谁负责

「计算订单总价」应分给 Order，因为 Order 拥有订单项；而不是丢给界面或工具类。

08 · 场景配对

① 开闭原则（对扩展开放、对修改关闭）
② 里氏替换原则
③ 接口隔离原则

⚠️

易错点：「多对多」一定要拆中间类；include 是必然、extend 是条件；聚合空心、组合实心。
